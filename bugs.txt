From pi session alias `pi-8391d3`, direct c2c sends to a live subagent alias failed through the relay with `signature_invalid`. The relay verified signer `pi-8391d3`, but the message body used host-qualified `from_alias` `pi-8391d3@3d08761ae3f3`, and the relay rejected the mismatch.

### Actual result
All direct sends failed with:

```json
{
  "ok": false,
  "error_code": "signature_invalid",
  "error": "verified signer \"pi-8391d3\" does not match body from_alias \"pi-8391d3@3d08761ae3f3\""
}
```

### Expected result
A sender registered as alias `pi-8391d3` with relay address `pi-8391d3@3d08761ae3f3` should be able to send to live peer `pi-8391d3-ad77e72`. Either:
- the relay signature check should normalize/accept host-qualified aliases for the same verified base alias, or
- the pi-c2c sender should set `from_alias` to the unqualified signed alias when signing as `pi-8391d3`.

- `c2c_pi_join_room(room="autoplanet")` also failed, but separately, with:

### Suspected cause
The relay signs/verifies the base alias (`pi-8391d3`) while the outbound body contains the host-qualified relay address (`pi-8391d3@3d08761ae3f3`) as `from_alias`. This appears to be an alias normalization/signing mismatch in the relay send path.
