# H3 — monitor identity + error honesty

Slice: friction-h3-monitor-truth (base c8d5e7c9).

## Symptom / defects closed
- `c2c monitor` peeked the relay inbox at `cli-<alias>` — the `relay register
  --alias` convention — even when the relay CONNECTOR managed the broker and had
  registered the alias under the machine node-id with the LOCAL session-id. Result:
  cross-host DMs piled up in the connector-managed inbox while the monitor watched
  an empty one forever. A014/A015; B111.
- The relay watcher extracted `messages` and discarded the `ok` flag, so an
  `{ok:false, error_code, error}` response (auth/identity/bad-request/connection)
  surfaced NOTHING and the loop spun forever against a dead-but-silent relay stream
  — "misleading success". B027/B181/B182/B190; A038.
- No exit-code taxonomy: terminal auth/identity failures never exited; transient
  and terminal errors were indistinguishable. B182/B196.

## Root cause
- `C2c_monitor_logic.decide_relay_watch` hard-coded `base = "cli-" ^ alias`.
- `extract_relay_messages` ignored `ok`; the loop `try…with` logged every error the
  same way and always continued.
- `relay_client.request` never raises (network/timeout/invalid-json map to
  `{ok:false, error_code:"connection_error"}`), so errors arrived as data the
  watcher threw away.

## Fix
- `resolve_relay_peek_key` + `~connector_key` on `decide_relay_watch`: when
  `connector-state.json` lists the resolved alias, default peek key becomes
  (connector node-id, local session-id). Connector now persists `node_id` in
  connector-state (additive; falls back to `Host_id.compute_host_hash`). Explicit
  `--relay-node-id`/`--relay-session-id` still win.
- `classify_relay_response` → `Peek_ok | Peek_transient | Peek_terminal`;
  `is_terminal_error_code` taxonomy (auth/identity/bad-request = terminal).
  Monitor loop: transient → backoff + retry + `reconnected` on recovery; terminal
  → clear stderr + `exit 3`. First peek fires immediately so terminal auth surfaces
  at startup.
- Exit taxonomy: 0 clean / 1 usage-startup / 3 terminal-relay.

## Live proof (read-only public HTTPS relay, 2026-07-10)
- `POST https://relay.c2c.im/peek_inbox` valid key → `{"ok":true,"messages":[]}` (Peek_ok).
- missing session_id → `{"ok":false,"error_code":"bad_request",...}` (Peek_terminal → exit 3).
Locked into `test_classify_real_relay_json_strings`.
