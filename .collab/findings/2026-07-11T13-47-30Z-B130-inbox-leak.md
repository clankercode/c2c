# B130 — c2c DM leaks into an unrelated dispatched subagent's transcript

- **Severity**: HIGH (cross-context isolation / privacy)
- **Status**: FIXED on `bl/B130-inbox-isolation` (stdin-`agent_id` gate)
- **Author**: subagent (B130 fixer), dispatched by coordinator

## Symptom

A coordinator Claude Code session (`c2c init`, CLI-only, `c2c monitor`) received
a DM. The DM reached the coordinator (correct) AND the full DM body surfaced
inside an UNRELATED dispatched Task subagent's transcript.

## Root cause (evidenced)

Claude Code fires the c2c PostToolUse hook during a dispatched subagent's tool
calls. The subagent shares the parent's `session_id`, so the hook resolved the
owner inbox, drained it, and injected the DM as `additionalContext` — which
Claude routed into the active (subagent) turn's transcript.

## The critical dead-end: env is NOT a discriminator

The first fix attempt gated on `CLAUDE_CODE_CHILD_SESSION=1`, believing it marked
Task subagents. **That is false and was a merge-blocking regression.** Empirical
evidence (Claude Code 2.1.207, `/proc` + a controlled headless capture):

- The top-level `claude` process does NOT carry the var, but EVERY tool
  subprocess (Bash shell, CLI, hook) of EVERY session — top-level AND subagent —
  is spawned with `CLAUDE_CODE_CHILD_SESSION=1`.
- A top-level tool shell and a dispatched subagent were IDENTICAL on
  `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_SESSION_ID`, and `ppid`.
- Every hook fire (SessionStart/PostToolUse/Stop, top-level and subagent) ran
  with `CLAUDE_CODE_CHILD_SESSION=1`.

So an env-based guard either (a) suppressed c2c delivery/onboarding/CLI for ALL
top-level sessions (regression — `c2c poll-inbox` refused a real coordinator), or
(b) was dead code. `session_id`, `ppid`, and `transcript_path` (derived from
session_id) are all shared too — none discriminate.

## The real discriminator: hook STDIN `agent_id`

Claude Code's hook input builder emits `agent_id` + `agent_type` into the hook
STDIN JSON, and its OWN subagent check is `isSubagent = !!agent_id`. Controlled
capture (headless `claude -p`, isolated config, stdin-logging hook) confirmed:

| turn | event | `agent_id` | `agent_type` |
|------|-------|-----------|--------------|
| top-level | SessionStart / PostToolUse / Stop | absent | absent |
| subagent | PostToolUse (its tool calls) | `"aeef9af5df9dd1744"` | `"general-purpose"` |
| subagent | SubagentStop (distinct event; c2c doesn't hook it) | present | present |

`agent_id` is emitted near the FRONT of the payload (before `tool_input`/
`tool_response`), so a bounded prefix scan finds it even with a huge tool
response. Subagents do NOT fire SessionStart, and fire `SubagentStop` (not
`Stop`) at turn end — so the sole live leak path is subagent PostToolUse.

## Fix

- **Gate hook drain/inject on a non-empty stdin `agent_id`** (new
  `C2c_hook_lib.stdin_is_subagent_turn`, reading a memoized single stdin slurp).
  Applied to the PostToolUse path (CLI `c2c hook post-tool` + standalone
  `c2c_inbox_hook`), and defensively to Stop and SessionStart. Exact: subagent
  turns suppressed; top-level turns (with or without the env var) deliver.
- **Removed the env-based `CLAUDE_CODE_CHILD_SESSION` gating** everywhere it
  misfired: `is_subagent_context` is back to the B042 `C2C_NO_AUTO_REGISTER`
  opt-out ONLY; reverted the cold-boot / post-compact env guards.
- **Deleted the CLI `refuse_if_subagent_implicit` guard**: bare
  `c2c inbox`/`poll-inbox`/`wait-inbox`/`peek-inbox` have NO hook stdin and
  cannot distinguish caller type — any env guard there regresses the
  "CLI: always-available fallback" goal. Left an explicit NO-guard note.

## Regression tests (both directions)

- `test_c2c_hook_claude`: subagent SessionStart (payload `agent_id`) → suppressed,
  DM not drained; top-level SessionStart with `CLAUDE_CODE_CHILD_SESSION=1` in env
  → DM delivered/drained; `is_subagent_context` is opt-out-only (CHILD_SESSION
  does NOT flip it).
- `test_session_id_delivery` (`b130-hook-gate`): PostToolUse hook with payload
  `agent_id` → no drain; top-level PostToolUse (no agent_id, CHILD_SESSION=1 env)
  → drains + delivers.

## Not c2c-fixable (harness boundary)

MCP `poll_inbox`/`peek_inbox` handlers and the inner MCP-server watcher run in
the shared PARENT MCP server process (a Task subagent shares the parent server;
it does not spawn its own), which has no per-RPC subagent provenance and no hook
stdin. They cannot be gated. They are also the explicit tool-call surface, not
the passive-injection leak. Recommend a harness-side change (subagent identity
in MCP calls) if that surface ever needs isolation.
