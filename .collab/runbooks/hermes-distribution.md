# Hermes distribution and update ownership

The plugin and its bundled skill target a general cross-platform audience.
Do not encode personal paths, LAN endpoints or machine-specific defaults.

## Canonical source → embed → install

- Runtime and Hermes-specific skill: `data/hermes-plugin/`, including
  `skills/c2c/SKILL.md`. This skill is **not** generated by
  `tools/ci/codegen-c2c-skills.py` (that assembles other harnesses), and
  `just sync-skills` does **not** update it.
- `just codegen-hermes-plugin` embeds the source files byte-for-byte into
  `ocaml/cli/c2c_hermes_plugin_embedded.ml`. Commit source and embed together.
- `C2c_setup.setup_hermes` installs `C2c_hermes_plugin_embedded.files`; plugin
  registration exposes the bundled skill. Updating a personal skill copy alone
  never fixes the distribution. Fold operational lessons back into canonical
  skill guidance in the same change as runtime/docs updates.
- Rebuild through `just build` or the normal build-box workflow, then run the
  resulting binary's `c2c install hermes` for the **intended profile** (using
  that profile's `HERMES_HOME`). Restart/reload that host to load updated Python
  and skill catalogues. Do not update unrelated profiles or assume installing
  a new binary refreshes an already installed plugin.

Before committing, run:

```sh
just codegen-hermes-plugin
just check-hermes-distribution
```

`just check` and CI run the read-only gate before build codegen can mask stale
committed output. It compares the complete source inventory with the embed,
including the skill; missing new files and changed skill bodies fail. Add new
runtime files to the existing generator recipe, not a second generator.
Regression tests prove stale canonical and installed skills fail the CLI gate.
The check deliberately does not judge prose meaning: when wake/identity/ACK or
setup behavior changes, review `docs/clients/hermes.md` and the bundled skill.

An optional explicit installed-directory audit is read-only:

```sh
python3 tools/ci/check-hermes-distribution.py --installed-dir "$HERMES_HOME/plugins/c2c"
```

Set `HERMES_HOME` to the intended profile first. The gate never infers a
personal profile and does not overwrite an installation or consent settings.

## Telegram transport owner

Audited companion source: `c2c-telegram-plugin` commit
`33fc657` is the audited 38-arrow baseline; the operator subsequently selected
a 19-arrow title, retained as native `pre.language` metadata below. The companion
19-arrow implementation is companion commit `a3599fd`. Installation and Telegram
client rendering still require their own evidence; do not infer them from source.
Its portable handoff is
`docs/upstream-silent-cards.md` in that repository. This is a separate
installation: this c2c embed neither contains nor updates that sender.

This repository does **not** contain the Telegram sender. B378 intentionally
leaves transport to the companion `c2c-telegram-plugin` repository; the canonical
plugin here provides shared message semantics and local CLI/TUI presentation.
Do not add a competing Telegram sender or monkey patch Hermes's global adapter.

The companion's single Telegram owner must supply
`disable_notification=True` explicitly on **every** `send_message` call:
first and subsequent chunks, both inbound peer cards and outbound completion
cards. Keep `parse_mode=None`, native UTF-16 entities, route/consent checks and
ACK-retention behavior intact. Verify the actual sender call kwargs in that
repository's incoming/outgoing multi-chunk tests. A skill statement or this
repository's source gate cannot establish silent delivery at runtime.

### Directional presentation contract

- Outgoing body-only native `pre`, with the exact companion title
  `language='➤➤➤➤➤➤➤➤➤➤➤➤➤➤➤➤➤➤➤'`
  (19 U+27A4 characters), on every body-bearing UTF-16 chunk. Copy this value
  verbatim; the title is entity metadata, never body/header text. Remove the
  obsolete outgoing separator row and `expandable_blockquote` recommendation.
- Incoming regular `blockquote` remains unchanged, with 17 spaced left arrows
  outside body entity ranges. Never include presentation arrows in peer bodies.
- Preserve literal bodies subject only to existing host redaction, omit
  zero-length body entities, and keep `parse_mode=None` and explicit
  `disable_notification=True` for every chunk in both directions.
- Validate formatter regressions and real `MessageEntity` SDK-boundary tests,
  including serialized `language` metadata. Mocks prove kwargs, not client UI
  or sound. Keep history observation, completion-only outbound observation,
  ambiguity-safe no-retry semantics, route/consent checks and ACK retention.
- Keep general-audience ownership comments near companion entrypoint,
  transport and observer; use supported profile APIs/configuration, never local
  chat IDs, profile restrictions, identities, paths or grants. Do not introduce
  a global notification toggle or change non-Telegram presentation.
- Refresh a copied companion through its supported installer, then use
  supported disable/enable hot reload on only the authorized target. A symlink
  follows its checked-out source. Read back intended-profile configuration,
  runtime registration and worker binding; never restart the gateway just to
  reload this plugin. This documentation fold-in does not activate an install.

Record standalone and upstream commit IDs, test receipts, generated-artifact
status and installed-version proof (or explicitly not installed) in the handoff.

When changing this integration, coordinate companion ownership, validate its
transport tests, and fold relevant operational guidance into the canonical
Hermes skill here. Never copy a local-only fix and call upstream complete.
