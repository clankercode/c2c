# B126 — agent-facing changelog feature

Status: implemented (slice/B126-changelog)
Author: (B126 slice agent)
Date: 2026-07-11

## Goal

Agents should learn about new c2c features (e.g. the codex-hook delivery
method, alias suggestions) when the binary version changes, and be able to
offer to set them up. Two surfaces:

1. `c2c changelog` — on-demand subcommand showing recent entries.
2. Auto-show on version update, per-client — at session start, when the
   running binary version differs from the last version whose changelog we
   auto-showed *for that client*, surface the new entries once, then persist
   a per-client marker.

## Canonical source of truth

`data/changelog/CHANGELOG.md` — a human-editable Markdown file. A version
section (`## v<semver> — <date>`) contains one or more **feature entries**,
each a `### <title>` block with `key: value` fields:

```
## v0.10.0 — 2026-07-11

### Codex hook-based delivery
summary: Codex sessions now receive inbound c2c messages through hooks …
setup: c2c install codex
clients: codex
audience: all
```

Per-entry fields (parent-specified agent-facing spec):
- `title` — one line, feature-oriented (the `### ` header).
- `summary` — 1-3 sentences addressed TO the agent (what it can now do
  differently), may span several continuation lines.
- `setup` (optional) — the **verbatim** command an agent can offer/run to
  adopt the feature (rule #414 — copied byte-for-byte through embed+parse; a
  test asserts `c2c install codex` survives verbatim).
- `clients` (optional) — subset of `claude|codex|opencode|kimi|gemini`;
  session-start injection filters to the current client, `c2c changelog`
  shows all. Empty = all clients.
- `audience` (optional) — `interactive|autonomous|all` (default `all`).

Header grammar: `## v<semver> — <date>` (em-dash, en-dash, or ` - `
accepted; date optional; a header without a digit in the version is ignored,
so `# c2c changelog` and prose are skipped). `summary` continuation = any
non-`key:` line until the next `###`/`## `.

### Why a checked-in Markdown file + embedded blob

- **Zero-latency common case**: the file is embedded into the binary at
  build time (codegen, mirroring `data/c2c_alias_words.txt` →
  `ocaml/c2c_alias_words.ml`). A binary always ships the changelog for every
  version it knows about, so `c2c changelog` and the auto-show never need the
  network for the versions the binary was built with.
- **GitHub fill-in**: for entries the local binary does *not* embed (older
  binary, richer upstream entries), a background fetch of the same file from
  GitHub raw fills a local cache. This is the "download missing changelogs in
  the bg" path from the task.
- **Public docs stay in sync**: the Markdown file is the same artifact humans
  read.

### Embedding mechanism

- `tools/ci/codegen-changelog.py` reads `data/changelog/CHANGELOG.md` and
  writes `ocaml/cli/c2c_changelog_embedded.ml` as a single verbatim OCaml
  quoted-string (`let changelog_md = {c2cchangelog|…|c2cchangelog}`). The
  script errors if the content contains the closing delimiter.
- `just codegen-changelog` regenerates; `just codegen-changelog-check`
  (wired into `just check`) fails on drift. A byte-for-byte drift unit test
  (`test_c2c_changelog`) pins the embed to the data file.

## Runtime module — `ocaml/cli/c2c_changelog.ml`

Pure parser + state machine + fetch:

- `type entry = { version; date : string option; title : string; summary :
  string; setup : string option; clients : string list; audience : string }`.
- `parse : string -> entry list` — parses the Markdown grammar above.
- `filter_client ~client` / `filter_audience ~audience` — the state layer's
  support for the surfacing filters.
- `compare_version` — numeric-dotted semver compare, string fallback.
- `embedded_entries ()` — parse the embedded blob (memoised).
- `remote_cache_path ~broker_root` = `<broker_root>/changelog/remote.md`;
  `merged_entries ~broker_root` = embedded ∪ remote-cache, deduped by
  version (embedded wins), sorted newest-first.
- `marker_path ~broker_root ~client` =
  `<broker_root>/changelog/last-shown-<client>.txt` (contains one version
  string). Atomic writes via `C2c_io.write_file_atomic`.
- `render_human` — plain text for the CLI.
- `render_changelog_for_agent ~current_version (entries) : string` — the
  **single seam** for the session-start injected copy. Its body is v0
  placeholder text; the surfacing layer (phrasing so the agent OFFERs setup,
  once-only-show wording) is owned separately and can be reworked without
  touching the fetch/cache/state plumbing. `auto_show` depends only on its
  type (`entry list -> string`).
- `spawn_background_fetch ~broker_root` — non-blocking. Fixture-gated:
  - `C2C_CHANGELOG_FETCH_FIXTURE=<path>` → copy that file straight to the
    cache synchronously (deterministic for tests; no network).
  - otherwise spawn a detached `curl -fsSL <raw-url> -o <tmp> && mv` child
    (parent never waits → never blocks). `C2C_CHANGELOG_FETCH_DISABLE=1`
    makes it a no-op.
  - The raw URL is `https://raw.githubusercontent.com/clankercode/c2c/master/data/changelog/CHANGELOG.md`.
- `auto_show ~broker_root ~client ~now : string option` — the state machine
  (below).

### Auto-show state machine (per client)

`auto_show ?current ?audience ~broker_root ~client ~now ()`. Let
`V = current (default Version.version)`, `L = marker(client)`. Marker
semantics per the parent's surfacing contract: the marker records the last
version actually **injected** for that client; advance it only after a real
emit, and only when entries covering `(L, V]` were locally available.

1. `L = Some V` → already injected → `None`.
2. `L = None` (fresh install) → write marker `V`, warm cache if stale, `None`
   (no update to announce, no history dump).
3. `L = Some prev`, `V ≤ prev` (downgrade/equal) → `None`, marker untouched
   (never regress).
4. `L = Some prev`, `V > prev` (upgrade):
   - Warm the cache if stale (non-blocking bg fetch) — the "1st launch fetches
     missing changelogs" step.
   - **Coverage** = does `merged_entries` contain an entry at version `V`? The
     binary always embeds its own version, so this is true on the common
     upgrade path; false only for a binary older than the entries it is asked
     to surface (remote-only). If not covered → `None`, marker untouched
     (2nd-launch shows once the fetch lands).
   - Covered → `new = entries_since prev |> filter_client ~client |>
     filter_audience ~audience`.
     - `new = []` (nothing for this client/audience) → `None`, marker
       untouched (advance only after a real emit; re-eval is cheap/idempotent).
     - `new ≠ []` → render via `render_changelog_for_agent`, advance marker to
       `V`, return `Some block`. With the embed this fires on the *first*
       launch after an upgrade.

## Session-start integration

`c2c hook claude` and `c2c hook codex` already assemble a SessionStart
`additionalContext` from ordered parts (intro, post-compact, cold-boot,
messages). We add a `changelog_context` part (only on `event =
"SessionStart"`, wrapped in `try … with _ -> ""` so it can never break the
turn) computed via `C2c_changelog.auto_show ~broker_root ~client ~now`.
Client is `"claude"` / `"codex"`. Grok/other clients are unaffected.

## `c2c changelog` subcommand

Tier1 (safe for agents). Flags:

- `--since <version>` — only entries strictly newer than `<version>`.
- `-n <count>` / `--limit` — cap number of entries (default 5).
- `--all` — all known entries.
- `--json` — machine-readable.
- `--fetch` — foreground refresh of the remote cache (fixture-gated), then
  print.

When no entries are available locally at all (shouldn't happen with the
embed, but defensive), it prints a hint pointing at the GitHub source.

## Testing

`ocaml/cli/test_c2c_changelog.ml` (Alcotest):
- parse a sample changelog → entries with versions/titles/body.
- `compare_version` ordering.
- `entries_since` filtering.
- `auto_show`: first-run bootstrap (marker written, no output), upgrade
  shows once (+ marker advances), re-launch at same version is silent,
  remote-only entries wait until cache populated then show.
- background fetch fixture: cache file written from the fixture path.
- embedded blob parses and is non-empty; drift check vs `data/…`.

All network gated behind `C2C_CHANGELOG_FETCH_FIXTURE`; no live network in
tests.

## Ownership split (scope steer, 2026-07-11)

- **This slice (plumbing)**: source format + storage, embedded entries, GitHub
  fetch (fixture-gated), background download + cache, `c2c changelog`,
  version-change detection, per-client last-shown state, tests, this doc.
- **Surfacing layer (separate owner)**: the exact injected text/markup at
  session start — how entries are phrased so an agent knows to OFFER setting
  up new features, and the once-only-show wording. Isolated behind
  `C2c_changelog.render_changelog_for_agent`; the copy in this slice is **v0
  placeholder** and is meant to be reworked there without touching plumbing.

## Out of scope (v1)

- Interactive per-feature setup wizards. We surface the info + setup hints so
  the agent can *offer* setup; we don't drive it.
- Relay/remote transport of changelog. GitHub raw is the only remote source.

--- SUMMARY ---

- Canonical changelog is `data/changelog/CHANGELOG.md`, embedded into the
  binary via a Python codegen step (`c2c_changelog_embedded.ml`), mirroring
  the alias-words pattern; a `--check` drift gate + unit test pin it.
- `C2c_changelog` provides a pure parser, semver compare, embedded/remote
  merge, a per-client "last-shown version" marker (atomic writes under
  `<broker_root>/changelog/`), rendering, and a fixture-gated non-blocking
  background GitHub fetch.
- `auto_show` state machine: nothing on same version; bootstrap (marker only)
  on first run; on version change show new entries once and advance the
  marker — deferring to a later launch only when the needed entries aren't
  locally available yet (the fetch-then-show path).
- Wired into `c2c hook claude` / `c2c hook codex` SessionStart assembly,
  try-guarded so it can never break a turn.
- `c2c changelog` subcommand (Tier1) with `--since/-n/--all/--json/--fetch`.
- Tests cover parsing, compare, filtering, the full state machine, and the
  fetch fixture; all network is fixture-gated (no live network in tests).
